# そろばん特訓アプリ 仕様書

> 原本: Claude Docs「そろばん特訓アプリ 仕様書」（2026-10-02）。このファイルはリポジトリ内の正本コピー。仕様変更時は両方を更新すること。

## 概要・目的

そろばん学習者が「見て→頭で考えて→弾く」から「見たら指が勝手に動く」へ移行するための特訓アプリ。最終目標はフラッシュ暗算。

- **核となる考え方**：1桁の加減算は「今の珠（0〜9）×足す/引く数（1〜9）」の有限パターン。詰まるパターンを計測して特定し、そこだけを反復して自動化する
- **紙のそろばんにない価値**：自分がどのパターンで詰まっているかが数値でわかること
- **役割分担**：運指の型（どの指で弾くか）は実物のそろばんで練習。アプリはパターン自動化と珠のイメージ化に特化する
- **ターゲット**：まず開発者自身（大人の独学者）。その後、そろばんを習う子ども・大人の学び直し層
- **仮アプリ名**：未定（例：珠トレ）
- **Android パッケージ名**：`com.meisme.soroban`

## 技術構成

脳内盤アプリ・定石帳と同じ構成を踏襲し、ノウハウを使い回す。サーバーなしの完全クライアント完結。

| 項目 | 採用 | 備考 |
|---|---|---|
| フロント | React + TypeScript + Vite | PWAとして開発 |
| ネイティブ化 | Capacitor | Android先行、iOSは反応を見て判断 |
| そろばん描画 | SVG（Reactコンポーネント） | 珠のアニメーションはCSS transition |
| 記録保存 | IndexedDB | パターン別の反応時間・正誤を保存 |
| 音声（後回し） | Web Speech API | 読み上げ算用。読みはカタカナで渡す |
| 課金（後回し） | RevenueCat | 買い切りアンロック |
| プレビュー | GitHub Pages | スマホ実機で確認 |

## 画面・モード構成

タブはホーム／苦手マップ／設定の3つ。モードは段階順に01〜05とし、MVPは01・02のみ。

| モード | 内容 | MVP |
|---|---|---|
| 01 パターン診断 | 1桁の加減算をランダム出題し、画面のそろばんで弾いて回答。全パターンの反応時間・正誤を計測 | ○ |
| 02 苦手集中 | 遅い・間違えるパターンだけを間隔反復で出題。基準タイム以内で連続正解したら卒業 | ○ |
| 03 珠の瞬間読み | 珠の配置を一瞬表示→数字で回答。逆に数字→珠の形を思い浮かべて答え合わせ | 次 |
| 04 補助輪付きフラッシュ暗算 | 数字＋珠の動きを表示→段階的に珠を薄く→数字のみ | 次 |
| 05 エアそろばん | 数字だけ流し、合計を入力 | 次 |

**画面のそろばん（共通部品）**

- 1桁モードは1本、多桁は最大5桁程度。五珠1つ＋一珠4つ
- 珠は指で掴んで上下に動かす。動かした方向の珠は押し出され、反対側の珠はその場に残る（実物と同じ）
- 指を離した時点で各珠を近い方へ寄せて配置を確定する。指を置いている間は確定・判定しない
- 弾いた勢いは少しだけ反映する。動かさずに離した場合はタップとして入れる／払うをトグル
- 珠を動かして正解の配置になった瞬間に自動で正解判定し、正解エフェクトを出して次の問題へ進む
- 「確定」ボタンはそのときのそろばんの状態で回答を確定する（正解に届かないまま答える＝誤答扱い）
- 表示オプション：珠の表示オン/オフ、定位点、桁の区切り

**考え方ヘルプ**

- 出題中、右上の「?」でその問題の考え方を表示する：分解の式（例 `+4 = +5 −1`）、その方法になる理由、珠の動かし方の手順、珠の動きのお手本アニメーション（シートを閉じるまで繰り返し再生）
- ヘルプを見ている間も計測は続ける（遅くなる＝苦手として扱われる）。ヘルプを見た回答は attempts に `hinted: true` を記録し、苦手集中では正解でも箱を上げない
- 誤答時の解説にも分解の式を出す
- ホームから「考え方ガイド」：4分類の説明と例、5・10の相方（補数）の早見表、±1〜9 の唱え方
- 苦手マップのマスの詳細からも考え方を開ける

**苦手マップ**

- 今の珠（0〜9）×足す数（1〜9）の表を、加算・減算それぞれで表示
- セルの色で平均反応時間、印で誤答率を示す
- 「5をまたぐ」「10をまたぐ」「両方またぐ」の3分類ごとの平均も表示

## 出題・判定ロジック

出題単位は「パターン」＝（演算, 今の一の位, 足す/引く数）。加算90＋減算90の計180パターン。

**パターン定義**

- 加算：今の一の位 a（0〜9）＋ n（1〜9）。繰り上がり先として十の位を表示する
- 減算：a（0〜9）− n（1〜9）。借りが必要な場合に備え、十の位に1以上を置いた状態から出題
- 出題時は「現在の珠の状態」をそろばんに置いた状態で表示し、「+7」のように演算だけ見せる

**分類（苦手の傾向を見るため）**

標準的な珠の動かし方をシミュレートし、使った手順で4分類にタグ付けする。

| 分類 | 例 | 手順 |
|---|---|---|
| 直接 | 1+3, 7−2 | 珠をそのまま入れる・払う |
| 5の補数 | 3+4, 6−3 | 五珠を入れて一珠を払う（または逆） |
| 10の補数 | 8+5, 13−4 | 十の位に1入れて補数を払う（または逆） |
| 併用 | 5+6, 12−6 | 10の補数の中で5の補数も使う |

**計測**

- 反応時間：出題表示から正解の配置になった瞬間（誤答は「確定」）までのミリ秒
- 正誤：確定時のそろばんの状態が正解の値と一致するか
- 誤答時は正解の珠の動きをアニメーションで見せてから次へ

**苦手判定と苦手集中**

- 各パターンの直近5回の平均反応時間と誤答率を保持
- 基準タイム＝「直接」分類の中央値×1.2（設定で変更可）
- 苦手＝基準タイム超え、または直近5回で誤答あり
- 苦手集中は簡易ライトナー方式（箱1〜4）。正解で箱が上がり、誤答で箱1に戻る。箱4で基準タイム内に3回連続正解すれば卒業
- 1セッションは20問（設定で10/20/50）

## データ設計

IndexedDB に3ストア。パターンIDは `add-3-9` / `sub-2-7` の形式。

| ストア | 主キー | 主な項目 |
|---|---|---|
| attempts | 自動採番 | patternId, mode, correct, ms, sessionId, at, hinted |
| patternStats | patternId | category, recentMs（直近5件）, recentCorrect（直近5件）, box, streak（箱4での連続正解数）, graduated, count, updatedAt |
| settings | key | 1セッション問題数, 基準タイム倍率, 珠表示, 効果音 |

- patternStats は attempts から再計算できるキャッシュ扱い
- 設定画面に JSON エクスポート/インポートを用意（機種変更対策）

## デザイン方針

将棋アプリと同じ「静かな鍛錬」路線。ダークモード前提、和の余白、数字は等幅。

- そろばんは木目ではなく、暗い背景に珠が淡く浮かぶ抽象的な表現（フラッシュ暗算の「頭の中の珠」に寄せる）
- 珠のタップ領域は44px以上。片手・縦持ちで弾けるサイズ
- 正解は控えめな効果音＋珠が一瞬灯る。派手な演出はしない
- デザインは Claude Design で作成

## 課金・公開方針

将棋アプリの方針を踏襲し、基本無料＋買い切りアンロック。サブスクは採用しない。

- 無料：01 パターン診断、02 苦手集中、苦手マップ（回数制限なし）
- 買い切り：03〜05 と今後追加するモード
- 公開：Google Play（ME IS ME の組織アカウント）を先行。MVPは課金なしで先に出してもよい

## MVPスコープとロードマップ

MVPは「自分が毎日使って、苦手パターンが減っていくのを実感できる」ところまで。作り込みより先に一気に作り切る。

1. **MVP**：画面のそろばん部品、01 パターン診断、02 苦手集中、苦手マップ、IndexedDB保存。GitHub Pagesで実機確認
2. **自分で2週間使う**：基準タイムや卒業条件を調整
3. **v1.1**：03 珠の瞬間読み、04 補助輪付きフラッシュ暗算
4. **v1.2**：05 エアそろばん、多桁（2〜3桁）の見取り算
5. **公開**：Capacitorでアプリ化、Google Play公開、買い切り導入

**MVPでやらないこと**：音声読み上げ、課金、統計グラフ、アカウント・同期、運指（どの指か）の判定
